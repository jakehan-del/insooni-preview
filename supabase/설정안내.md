# 백엔드 켜는 방법

**약 15분.** 개발 지식은 필요하지 않습니다. 화면에서 클릭하는 순서대로 적었습니다.

지금 사이트는 백엔드 없이도 완전히 정상입니다. 사랑방의 편지·응원은 "이 기기에만 저장"으로
동작하고, 화면에도 그렇게 적혀 있습니다. 아래를 마치면 **실제로 인순이에게 전해지고,
팬들이 서로의 글을 보게** 됩니다.

---

## 1단계 — Supabase 계정 만들기 (5분)

1. https://supabase.com 접속 → 오른쪽 위 **Start your project**
2. GitHub 계정으로 로그인 (이미 저장소를 쓰고 계시니 이게 가장 빠릅니다)
3. **New project** 클릭
4. 이렇게 채웁니다
   - **Name**: `insooni-official`
   - **Database Password**: 아무 긴 문자열. **한 번 적어서 따로 보관**하세요.
     (이 비밀번호는 웹사이트에 넣지 않습니다. 나중에 DB에 직접 접속할 때만 씁니다)
   - **Region**: `Northeast Asia (Seoul)` — 팬 대부분이 한국에 있으니 서울이 가장 빠릅니다
   - **Plan**: Free
5. **Create new project** → 1~2분 기다립니다

---

## 2단계 — 표(테이블) 만들기 (2분)

1. 왼쪽 메뉴에서 **SQL Editor** 클릭
2. **New query** 클릭
3. 이 저장소의 `site/supabase/001_init.sql` 파일을 열어 **전문을 복사**
4. 편집창에 붙여넣고 오른쪽 아래 **Run** (또는 Ctrl/Cmd + Enter)
5. 아래에 `Success. No rows returned` 가 나오면 끝났습니다

> 이 SQL은 여러 번 실행해도 안전합니다. 실수로 두 번 눌러도 문제없습니다.

---

## 3단계 — 열쇠 두 개 가져오기 (1분)

1. 왼쪽 메뉴 아래쪽 **Project Settings**(톱니바퀴) → **API**
2. 두 값을 복사합니다
   - **Project URL** — `https://xxxxxxxx.supabase.co` 형태
   - **Project API keys** 항목의 **`anon` `public`** 키 — `eyJ...`로 시작하는 긴 문자열

> **`service_role` 키는 절대 복사하지 마세요.** 바로 아래에 같이 있어서 헷갈리기 쉽습니다.
> 그 키는 모든 보안 규칙을 무시하고 구독자 이메일까지 전부 읽고 지울 수 있습니다.
> 저장소가 공개이므로 넣는 순간 누구나 가져갈 수 있습니다.

---

## 4단계 — 사이트에 붙여넣기 (2분)

`site/assets/js/config.js` 파일을 열어 두 줄만 채웁니다.

```js
if (!window.INSOONI_CONFIG.url) {
  window.INSOONI_CONFIG.url = "https://xxxxxxxx.supabase.co";
}
if (!window.INSOONI_CONFIG.anonKey) {
  window.INSOONI_CONFIG.anonKey = "eyJhbGciOi...";
}
```

저장하고 배포하면 끝입니다. 사랑방을 열어 보면

- 팬레터 제목이 **"도착한 편지들"** 로 바뀝니다
- **팬 게시판**이 나타납니다 (지금은 숨어 있습니다)
- **소식지 신청 칸**이 나타납니다
- 신청곡이 **"지금 가장 많이 신청된 노래"** 로 바뀝니다
- 응원 벽이 **"오늘의 응원"** 으로 바뀝니다

키를 다시 비우면 즉시 원래대로 돌아갑니다. 되돌리기가 언제든 가능합니다.

---

## 5단계 — 매일 검수 (하루 2~3분)

팬이 보낸 편지와 글은 **바로 공개되지 않습니다.** 확인하신 것만 올라갑니다.

1. Supabase → **Table Editor**
2. `letters` 표를 엽니다
3. `status` 열이 `pending` 인 줄이 검수 대기입니다
4. 글을 읽고 그 칸을 클릭해
   - 올려도 되는 글이면 `approved`
   - 올리지 않을 글이면 `rejected`
5. `posts` 표도 같은 방식으로

승인하는 즉시 사이트에 나타납니다. 따로 배포할 필요가 없습니다.

**한 번에 몰아서 보고 싶으시면** SQL Editor에서:

```sql
select * from moderation_queue;
```

**아무것도 승인하지 않아도 사이트는 멀쩡합니다.** "아직 게시된 편지가 없습니다"라고
정직하게 표시되고, 팬이 보낸 편지는 그대로 보관됩니다.

## 구독자 이메일 보는 방법

웹사이트에서는 **어떤 방법으로도** 구독자 목록을 볼 수 없게 막아 두었습니다.
운영자만 Supabase에 로그인해서 볼 수 있습니다.

```sql
select email, created_at from subscribers order by created_at desc;
```

내려받기: Table Editor에서 `subscribers` → 오른쪽 위 **Export** → CSV

> 이 순간부터 개인정보를 보관하시는 것입니다. 소식지를 보내지 않기로 하셨다면
> 표를 비워 두는 것이 맞습니다:
> `delete from subscribers;`

## 무료 티어로 충분한가

| 항목 | 무료 한도 | 이 사이트 기준 |
|---|---|---|
| 데이터베이스 | 500 MB | 편지 한 통 ≈ 1 KB. 50만 통까지 |
| 통신량 | 5 GB / 월 | 사랑방 방문 수십만 회 분량 |
| 프로젝트 정지 | **1주일 접속이 없으면 일시 정지** | 아래 주의사항 참고 |

**주의 — 무료 프로젝트는 일주일 동안 아무 접속이 없으면 잠깁니다.**
잠기면 사랑방의 편지 목록이 "불러오지 못했습니다"로 표시됩니다(사이트 나머지는 정상).
Supabase 대시보드에서 **Restore** 한 번 누르면 되살아납니다.
팬 방문이 꾸준하면 잠기지 않습니다. 확실히 하려면 유료(월 $25)로 올리시면 됩니다.

## 잘 안 될 때

| 증상 | 확인할 곳 |
|---|---|
| "지금 보내지 못했습니다"만 나온다 | `config.js`의 URL 끝에 `/`가 붙지 않았는지. 키를 통째로 복사했는지 |
| 편지가 보내지는데 목록에 안 보인다 | 정상입니다. `status`를 `approved`로 바꿔야 나타납니다 |
| "잠시 뒤에 다시 보내 주세요" | 도배 방지가 걸린 것입니다. 한 시간에 편지 5통까지 |
| 모든 게 예전처럼 로컬로 동작한다 | 키가 비어 있습니다. 배포된 `config.js`를 브라우저에서 직접 열어 확인 |
| 목록 자리에 "불러오지 못했습니다" | 무료 프로젝트가 잠겼을 수 있습니다. Restore |

브라우저에서 **F12 → Console**을 열면 실패 이유가 함께 보입니다.

## 절대 하지 말아야 할 것

1. **`service_role` 키를 `config.js`에 넣지 마세요.** 저장소가 공개입니다.
2. **`001_init.sql`의 정책(policy) 부분을 지우지 마세요.**
   그 문장들이 "남의 글을 못 고치게", "구독자 이메일을 못 읽게" 막고 있습니다.
3. **`subscribers` 표에 읽기 정책을 추가하지 마세요.**
   지금은 정책이 없어서 아무도 읽을 수 없습니다. 그게 의도입니다.
4. Database Password를 웹사이트 파일에 넣지 마세요.
