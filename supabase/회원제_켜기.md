# 사랑방 회원제 켜기 (2026-10-02)

카카오 로그인 · 이메일 가입 · 새싹 → 정회원 등업 · 카페 게시판(공지·가입인사·자유·공연 후기)과 댓글.
화면과 서버 코드는 다 준비돼 있고, 아래 설정이 끝나면 켜집니다.
**열쇠(Client Secret 등)는 형님이 Supabase 화면에 직접 넣습니다. 저에게 보내지 마세요.**

순서대로 하시면 됩니다. 1번만 해도 이메일 가입은 바로 됩니다(메일 발송 한도가 낮을 뿐).

---

## 1. 서버 준비 — SQL 하나 실행 (1분)

1. Supabase 대시보드 → 왼쪽 **SQL Editor** → **New query**
2. `supabase/010_회원과_게시판.sql` 전체를 붙여넣고 **Run**
   ("Potential issue detected"가 뜨면 **Run query**)
3. 아래 결과 창에 **✅ 9개**가 뜨면 성공입니다.

- 009(알림)를 아직 안 하셨어도 010 하나면 됩니다. 010이 009를 포함합니다.
- 하나라도 어긋나면 SQL이 **스스로 전체를 취소**합니다. 아무것도 바뀌지 않으니 안심하셔도 됩니다.

## 2. 돌아올 주소 등록 (1분)

Supabase → **Authentication → URL Configuration**

| 칸 | 넣을 값 |
|---|---|
| Site URL | `https://insooni.com` |
| Redirect URLs (Add URL) | `https://insooni.com/**` |

가입 확인 메일·카카오 로그인이 끝나면 사랑방(`/community?bd=…`)으로 돌아옵니다. 빠지면 로그인 후 엉뚱한 곳으로 갑니다.

## 3. 회원가입은 **열어 둔 채로** 둡니다

Authentication → **Sign In / Providers**

- **Allow new users to sign up** → **켜 둡니다(ON).**
  ⚠️ 어제(10/01) "끄시라"고 말씀드렸는데, 그건 회원제가 없을 때의 이야기였습니다. 이제는 팬이 가입해야 하니 **켜 두셔야 합니다.**
  운영 화면은 따로 지켜집니다. 운영자 명단(admins)에 없는 계정은 가입해도 운영 화면에서 아무것도 못 합니다.
- **Email** 항목 → **Confirm email: ON** (가입하면 확인 메일이 갑니다. 기본값 그대로)

## 4. 카카오 로그인 (약 10분) — 공연장 QR 가입의 1순위

### 카카오 쪽 — https://developers.kakao.com (형님 카카오 계정으로 로그인)
1. **앱 → 앱 생성**(애플리케이션 추가하기)
   - 앱 이름: `인순이 사랑방` (팬이 카카오 동의 화면에서 보는 이름) · 회사명: 소솝 · 카테고리: 엔터테인먼트(또는 음악)
2. **앱 설정 → 앱 → 플랫폼 키** → **REST API 키**를 복사해 둡니다 (= Supabase 의 Client ID)
3. 같은 화면에서 **REST API 키를 눌러** 들어가서
   - **카카오 로그인 리다이렉트 URI** 에 추가: `https://vxrazyiqvdwgvgpkkitm.supabase.co/auth/v1/callback`
   - **카카오 로그인 클라이언트 시크릿** 코드를 복사하고, 활성화 **사용함** → 저장
4. **제품 설정 → 카카오 로그인 → 일반** → 상태 **ON**
5. **제품 설정 → 카카오 로그인 → 동의항목**
   - 닉네임: **필수 동의** · 프로필 사진: **선택 동의**
   - 카카오계정(이메일): **선택 동의** ← 꼭 켜 주세요. Supabase 가 로그인할 때 이메일 권한을 늘 함께 요청해서,
     이 항목이 꺼져 있으면 팬 화면에 **KOE205** 오류가 뜹니다.
   - ⚠️ **세 항목이 모두 '사용'이어야 합니다.** Supabase 는 카카오에 `account_email profile_image profile_nickname`
     **세 권한을 늘 함께** 요청합니다(라이브 실측 2026-10-02). 이메일만 켜고 **프로필 사진이 '사용 안 함'이면 똑같이 KOE205** 입니다.
     2026-10-02 밤 형님 폰 한 대로 가입이 된 뒤에도 "KOE205 오류도 나와"가 다시 왔습니다 — 세 항목을 다시 확인해 주세요.
     '권한 없음'으로 막혀 있으면 **앱 설정 → 비즈니스 → 개인 개발자 비즈 앱 전환**(본인인증만, 사업자등록 불필요) 뒤에 켜집니다.
   - 동의 목적 문구 예: `사랑방 회원 확인`

> 화면이 위와 다르면(옛 메뉴): 리다이렉트 URI 는 **제품 설정 → 카카오 로그인**, 시크릿은 **카카오 로그인 → 보안**에 있습니다.

### Supabase 쪽
Authentication → **Sign In / Providers → Kakao**
- **Enable Sign in with Kakao: ON**
- **Client ID** = 2번의 REST API 키
- **Client Secret** = 3번의 클라이언트 시크릿 코드
- **Allow users without an email: ON** (이메일 동의를 거절한 팬도 가입되게)
- **Save**

끝나면 아래 **7. 켜는 순서**의 ②(실제 가입 왕복)를 해 주세요. **카카오 동의 화면이 뜨는 것만으로는 합격이 아닙니다** —
KOE205 는 동의 화면 '다음'에서도 납니다. 시크릿 값은 저에게 보내지 마세요.

## 5. 메일 양식 바꾸기 — **꼭 해 주세요** (5분)

폰에서 메일 링크를 누르면 대개 **메일 앱 안의 브라우저**로 열립니다. 기본 양식은 "요청한 그 브라우저"에서만
이어져서, 어르신들이 비밀번호를 다시 정하다 막힙니다. 아래처럼 바꾸면 **어느 브라우저에서 열어도** 이어집니다.

Supabase → Authentication → **Emails → Templates**

**Confirm signup** (가입 확인)
- Subject: `인순이 사랑방 가입 확인`
- Body:
```html
<h2>인순이 사랑방</h2>
<p>아래 버튼을 누르면 가입이 이어집니다.</p>
<p><a href="{{ .SiteURL }}/community?token_hash={{ .TokenHash }}&type=email">가입 확인하기</a></p>
<p>직접 가입하지 않으셨다면 이 메일은 무시하셔도 됩니다.</p>
```

**Reset Password** (비밀번호 다시 정하기)
- Subject: `인순이 사랑방 비밀번호 다시 정하기`
- Body:
```html
<h2>인순이 사랑방</h2>
<p>아래 버튼을 누르면 새 비밀번호를 정하는 화면이 열립니다.</p>
<p><a href="{{ .SiteURL }}/community?token_hash={{ .TokenHash }}&type=recovery">비밀번호 다시 정하기</a></p>
<p>요청하지 않으셨다면 이 메일은 무시하셔도 됩니다. 비밀번호는 바뀌지 않습니다.</p>
```

(바꾸지 않아도 같은 브라우저에서 열면 이어집니다. 화면은 두 방식을 모두 받습니다.)

## 5-1. 메일 발송 서비스 연결 (권장, 15분)

Supabase 기본 메일은 **시간당 2통**까지만 보냅니다. 가입 확인·비밀번호 재설정 메일이 막히면
화면에 "지금은 메일을 보낼 수 없습니다 … 카카오로 시작해 주세요"라고 정직하게 뜨긴 하지만,
이메일 가입이 사실상 안 됩니다. 카카오만 쓰실 거면 건너뛰셔도 됩니다.

1. 메일 발송 서비스 하나에 가입(예: Resend — 무료 하루 100통)하고 `insooni.com` 도메인을 등록·인증
2. Supabase → Authentication → **Emails → SMTP Settings** → Enable custom SMTP
   - Host / Port / Username / Password: 그 서비스가 알려 주는 값
   - Sender email: `no-reply@insooni.com`, Sender name: `인순이 사랑방`

## 7. 켜는 순서 — 카카오(KOE205) · 공연 모드 (2026-10-02 밤)

사이트의 스위치는 `assets/js/config.js` 에 있고, **정확히 `true` 일 때만** 켜집니다(적지 않으면 꺼짐).

| 스위치 | 지금 | 뜻 |
|---|---|---|
| `board` | true | 회원·사랑방 카페 |
| `kakao` | **true** (10/02 18:31 형님 계정 왕복 확인 · 일반 계정 2개 시험은 아직) | 카카오 로그인 단추. false 면 Supabase 가 카카오를 켜 둬도 단추를 그리지 않는다(이메일만) |
| `live` | false | 공연 화면(/live)·사랑방 '오늘 공연' 줄 |
| `mypage` | false | 내 정보(community.html#me)의 **013 칸** — 내 댓글 모아 보기 · '내 노래' · 가입 질문 '좋아하는 인순이 노래(선택)' · 운영 화면 회원 탭의 내 노래. 꺼져 있어도 내 정보는 열립니다(별명·등급·내가 쓴 글·도장·별명 바꾸기·로그아웃·탈퇴) — 013 칸 자리에 '준비하고 있습니다' 한 줄 |
| `liveEmail` | false | 공연장 회원 창에서 이메일 '처음 가입'을 숨길지. **카카오가 꺼져 있거나 방금 실패했으면 이 값과 상관없이 이메일 가입을 엽니다**(처음 온 관객이 가입할 길이 0개가 되지 않게) |

켜는 순서:

1. **카카오 동의항목 세 개**(닉네임 필수 · 프로필 사진 선택 · 카카오계정(이메일) 선택)를 모두 '사용'으로. 이메일이 막혀 있으면 개인 개발자 비즈 앱 전환을 먼저.
2. **형님 폰이 아닌 일반 카카오 계정 2개**로, **카카오톡 인앱 1회 · 아이폰 사파리 1회** — 가입 마치기 화면까지 끝까지 왕복합니다.
   동의 화면이 뜨는 것만으로는 합격이 아닙니다. 어느 한 번이라도 KOE 로 시작하는 오류가 보이면 1번으로.
3. `config.js` 의 `kakao` 를 `true` 로 바꿔 배포.

> ### 0. 재설계 배포 — **10/3 14:00 KST(도장 열림) 전 마감** (2026-10-03 새벽 추가)
>
> **지금 운영 사이트에는 공연 화면이 없습니다.** 재설계 브랜치(`redesign` — 사랑방 v4 · 공연 화면 live.html·gig.js · 운영 공연 탭 · 마이페이지)는
> 아직 배포되지 않았고, 그래서 지금 QR 주소 `https://insooni.com/live?e=5UYX8` 는 **404**('페이지를 찾을 수 없습니다 | 인순이 INSOONI')입니다
> (10/3 08:15 KST 읽기 전용 확인: `curl -A Mozilla/5.0 https://insooni.com/live?e=5UYX8` → 404 · 제목 '페이지를 찾을 수 없습니다' ·
> 받아 둔 `origin/main` 에 `live.html` 없음 · 그 config.js 에 live·mypage 스위치 없음). 아래 4~5번보다 **이 배포가 먼저**입니다.
> 404 가 보이면 '고장'이 아니라 '아직 배포 전'입니다.
>
> 순서(push·배포는 형님이 직접 — 저는 push 하지 않습니다):
> 1. 작업 사본(`insooni-deploy-new`, 브랜치 `redesign`)의 변경을 커밋합니다.
> 2. 소식 작업(`insooni-news`)을 병합합니다 — `news.html`·`collect-news.py` 는 그쪽 것이 정본입니다. 충돌이 나면 HTML 의 `?v…` 꼬리표 줄은
>    어느 쪽이든 괜찮습니다(5번의 build.py 가 다시 씁니다).
> 3. `origin/main` 을 병합합니다(10/3 04:06 KST 자동 소식 커밋 `122722c` 등 — 라이브가 더 최신인 것을 되돌리지 않게).
> 4. `python3 scripts/collect-news.py --offline`
> 5. `python3 scripts/build.py` → 끝에 '축소본 구문 검사 17개 통과'와 새 `?v` 꼬리표가 찍히는지 봅니다.
> 6. 전체 검사(README 의 검사 순서) — 하나라도 ✗ 면 push 하지 않습니다.
> 7. push.
>
> 스위치(`assets/js/config.js`)는 둘 중 한 길로:
> - **(a) 안전한 두 번 배포** — `live: false` 그대로 먼저 올립니다 → 폰에서 `/live?e=5UYX8` 가 **'공연 화면은 곧 열립니다.'**(사랑방으로 링크 하나)로
>   열리면 배포 성공 → 아래 4·4-1·4-2(011·012·013) 실행 → `live: true`(013 뒤 `mypage: true`) → build.py → 다시 push.
> - **(b) 한 번 배포** — 4·4-1·4-2 SQL 을 먼저 실행하고 ✅ 를 확인한 뒤, `live: true`·`mypage: true` 로 한 번에 배포.
>
> 배포 뒤 확인(둘 다):
> - `curl -sA Mozilla/5.0 -o /dev/null -w "%{http_code}\n" "https://insooni.com/live?e=5UYX8"` → **200**,
>   `curl -sA Mozilla/5.0 "https://insooni.com/live?e=5UYX8" | grep -o "<title>[^<]*"` → **`<title>공연 도장 · INSOONI`**.
> - 같은 페이지 소스의 `gig.min.js?v…` 꼬리표가 5번에서 찍힌 것과 같은지(옛 캐시가 아닌지).
> - 폰(카카오톡으로 QR)에서 공연 이름 '진해아트홀 개관기념 인순이 스페셜 콘서트'와 '도장은 … 오후 2시부터'(14:00 전)가 뜨는지.
>
> 14:00 전에 형님 몫으로 하나 더:
> - **Supabase → Authentication → Rate Limits** 를 공연 인원에 맞게 올립니다(운영 화면 점검표 2번). 공연장 와이파이처럼 여러 사람이 IP 하나를 쓰면
>   카카오 왕복 마지막 단계(토큰 교환)가 429 로 막힐 수 있습니다. 화면은 그때 '카카오 로그인을 마치지 못했습니다. 잠시 뒤 카카오로 다시 시작해 주세요.'라고
>   말하지만, 한도를 올려 두는 것이 먼저입니다. 정확한 한도·적용 범위는 대시보드에 보이는 값을 따릅니다.
> - **Authentication → SMTP Settings** 에 커스텀 SMTP 가 연결돼 있는지 확인합니다. 없으면 기본 메일은 시간당 몇 통뿐이라 이메일 가입은 사실상 막힙니다
>   (그래서 화면은 카카오를 맨 위 주 단추로 둡니다).

4. Supabase SQL Editor 에서 `011_공연_모드.sql` 실행 → 결과 창 ✅ 1~10 확인.
   - 4-1. 이어서 `012_진해아트홀_공연_등록.sql` 실행 → Table Editor 의 `gig_events` 에 코드 **5UYX8** 한 줄이 있는지 확인.
     (012 를 빼먹으면 QR 주소가 '공연을 찾지 못했습니다' 화면으로 떨어집니다.)
   - 4-2. 이어서 `013_마이페이지_가입질문.sql` 실행 → 결과 창 ✅ 확인. 확인되면 `config.js` 의 `mypage` 를 `true` 로(5번 배포에 함께).
     013 없이 `mypage` 를 켜도 깨지지는 않습니다(내 정보가 010 칸으로 서고 가입은 그대로) — 다만 없는 함수를 부른 404 가 방문자 콘솔에 남으므로 013 이 먼저입니다.
5. `config.js` 의 `live` 를 `true` 로 바꿔 배포.
   - 배포 **전에** 한 번 더(**0번 재설계 배포 뒤에** — 그 전에는 404 입니다): `https://insooni.com/live?e=5UYX8` 를 열어, '공연 화면은 곧 열립니다'(스위치 꺼짐 · '사랑방으로' 링크 하나)가 보이면 정상입니다.
   - 체크: 011·012(·013) 실행 ✅ → `live: true`(013 뒤 `mypage: true`) → `python3 scripts/build.py` → 축소본 `?v` 꼬리표가 바뀌었는지 → push → `/live?e=5UYX8` 200 · 제목 '공연 도장 · INSOONI'.
     배포 **뒤에** 같은 주소가 공연 이름(진해아트홀 개관기념 인순이 스페셜 콘서트)과 함께 '도장은 … 부터'(14:00 전) 또는 '지금 도장을 찍을 수 있습니다'(14:00~21:00)로 열리는지 확인합니다.
     '공연을 찾지 못했습니다'가 뜨면 4-1 을 다시 확인합니다.
6. 운영 화면(insooni.com/admin) → 「공연」 탭 → **공연 전 점검표** 8줄.

**KOE205 가 다시 보이면 즉시 되돌립니다** — `config.js` 의 `kakao` 를 `false` 로 바꿔 배포(1분). 그동안 팬 화면에는 이메일 가입만 보입니다.
카카오 화면에서 코드 없이 돌아온 사람(동의 화면에서 뒤로 가기 · 인앱 창 닫고 QR 다시 찍기)에게는 원인을 단정하지 않고
'카카오 로그인이 끝나지 않았습니다. 카카오 화면에 KOE로 시작하는 오류가 보였다면 저희 설정 문제입니다…' 안내가 뜹니다.
공연 화면과 사랑방 모두 노란 '카카오로 시작하기'가 그대로 주 단추로 남고(사랑방은 맨 위, 공연 화면은 엄지 자리), 이메일 '처음 가입'도 함께 열립니다
(공연 화면은 접힌 '이메일로 가입·로그인' 안에). 카카오가 오류(error)를 돌려보낸 때에만 10분 동안 카카오 단추를 아래로 내리고 이메일을 앞에 둡니다.
카카오에서 돌아왔는데 마지막 열쇠 교환이 실패하면(요청 한도 429 등) 메일 이야기가 아니라 '카카오 로그인을 마치지 못했습니다. 잠시 뒤 카카오로 다시 시작해 주세요.'가 뜹니다.

## 운영 — 매일 할 일

- **insooni.com/admin** → 「검수 대기」에서 새싹의 글·댓글을 **올리기 / 내리기**
- **공지 쓰기**: 운영자 계정으로 사이트에 로그인 → 사랑방 「공지」 탭 → 글쓰기. 공지는 전체글 맨 위에 최근 3개가 고정됩니다.
  - 올리기를 누르다가 그 회원이 기준(글 3 · 댓글 5)을 채우면 화면에 "정회원이 되었습니다"가 뜹니다.
- 「회원」 탭 — 별명 찾기, **정회원으로 / 새싹으로 / 쉬게 하기(차단)**
  - 운영자가 한 번 등급을 정한 회원에게는 자동 등업이 다시 적용되지 않습니다.
- 등업 기준을 바꾸려면: Supabase → Table Editor → `board_settings` → `value` 숫자만 고칩니다.
- 운영자 추가: 그 사람이 사이트에서 이메일로 가입한 뒤, SQL Editor에서 아래를 실행합니다(이메일만 바꿔서).
  ```sql
  insert into public.admins (user_id, email, memo)
  select id, email, '매니저' from auth.users where email = '매니저이메일@example.com'
  on conflict (user_id) do nothing;
  ```

## 지켜지는 것

- 공개되는 것은 **별명과 등급뿐**입니다. 이메일·카카오 정보는 어떤 공개 목록에도 나오지 않습니다(운영자 화면에서도 가려서 보입니다).
- '인순이'·'운영자'·'관리자'·'공식' 같은 별명은 서버가 막습니다(띄어쓰기·영문으로 바꿔도).
- 탈퇴하면 그 사람의 글·댓글·등급 기록이 **즉시 함께 지워집니다.** 운영자 계정은 실수로 지워지지 않게 사이트에서 탈퇴할 수 없습니다.
- 운영자 '내리기'는 지우는 것이 아니라 숨기는 것입니다. 지우는 것은 쓴 사람 자신뿐입니다.
- 팬이 쓰던 글은 그 기기에 저절로 저장됩니다. 카카오 로그인으로 화면을 떠났다 와도, 실수로 창을 닫아도 남습니다.
